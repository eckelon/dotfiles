# Hyprland

Compositor config, idle management, themes and helper scripts. Deployed to
`~/.config/hypr/`. Files named `executable_*` in this repo lose the prefix and
land as executable scripts (`theme.sh`, …) once chezmoi applies them.

## Main configs

### `hyprland.conf`

- **Layout**: `scrolling` — windows sit in columns; one window fills the
  screen, a second splits it in halves, extras open as off-view columns you
  scroll to with `mod+arrows`. Column width via `mod+ctrl+arrows` (±5%,
  ±15% with shift, `mod+ctrl+0` resets to 50%).
- **Keybindings** (`$mod` = Super, physically on the Alt keys — keyd swaps
  Alt/Super): terminal, browser (Helium), walker launcher (`SUPER+SPACE`),
  clipboard history (`SUPER+SHIFT+C`), workspaces 1–5, float/fullscreen,
  mouse binds, brightness/volume/media keys via `bindel`/`bindl` (repeat
  while held), screenshot (`Print` → grim+slurp → wl-copy), lock (`SUPER+L`).
- **Window rules** match by *title* where Ghostty is involved — Ghostty 1.3
  ignores `--class` on Wayland, but `--title` survives map time:
  - `dotfloat` — the floating TUI popups waybar opens (alsamixer, netpanel, powertop).
  - `cheatsheet` — the `SUPER+?` keybinding overlay, a special workspace.
  - `Helium` — always fullscreen: the browser lives alone on its own
    workspace (see `helium-ws.py`), so the scrolling layout gives it the
    whole work area without a fullscreen flag.
- **Autostart order matters**:
  1. `theme.sh boot` — restores the last theme (writes the symlinks below)
     *before* waybar starts, because waybar imports the theme CSS.
  2. `elephant.service` then `walker --gapplication-service` — data backend
     first, then a warm walker instance so `SUPER+SPACE` pops instantly.
  3. `waybar`, `nwg-dock-hyprland`, `mako`, `hypridle`, polkit agent, and a
     `dbus-update-activation-environment` call so GTK apps get the Wayland env.
  4. `helium-ws.py` and `clipkeys.py` — event listeners, see below.
- **Input**: `kb_layout = us` + `kb_variant = altgr-intl` — the variant that
  pairs with keyd (see `dot_config/keyd/README.md`); `natural_scroll` set
  globally (Hyprland 0.56 ignores it inside per-device blocks for mice).

### `monitors.conf`

Generated by nwg-displays, **not versioned** — each machine keeps its own.

### `theme.conf`

Not a real file: a symlink to `themes/<name>/theme.conf` (see below), swapped
by `theme.sh`. It defines the `$col_active` / `$col_inactive` variables that
`hyprland.conf` uses for window borders.

### `hypridle.conf`

Three idle listeners: screen off (DPMS) after 5 min, `hyprlock` after 15 min,
system suspend after 16 min. `caffeinate.sh` (below) suspends these by
killing hypridle and inhibiting systemd.

## Themes

`themes/<name>/` — three themes, each two files:

| File | Feeds | Contains |
| --- | --- | --- |
| `theme.conf` | Hyprland borders (`$col_*` vars) | active/inactive gradient colors |
| `waybar.css` | waybar (`style.css` imports it) | `@define-color` palette |

Switching is a symlink swap + reload (no config regeneration):

- `~/.config/hypr/theme.conf` → `themes/<name>/theme.conf`
- `~/.config/waybar/theme.css` → `themes/<name>/waybar.css`

Current theme name and wallpaper are runtime state in
`~/.config/hypr/.theme` / `.wallpaper` (not chezmoi-managed).

## Scripts

### `theme.sh` — theme + wallpaper switcher

```sh
theme.sh list          list themes
theme.sh set <name>    apply theme (borders + waybar)
theme.sh next          cycle themes            (SUPER+T)
theme.sh wall <file>   set wallpaper (all monitors, via hyprpaper)
theme.sh walln         cycle ~/Pictures/wallpapers   (SUPER+SHIFT+T)
theme.sh boot          exec-once: restore theme, start hyprpaper
```

### `caffeinate.sh` — macOS-style caffeinate

`on|off|toggle|status|icon`. Blocks idle timers, suspend and lid switch
(`systemd-inhibit`) so the laptop stays reachable over SSH; works without a
Wayland session. `off` restarts hypridle fresh (frozen stale timers would
fire on resume). `icon` emits the JSON for waybar's `custom/caffeine` module.
Bound to `SUPER+X` and the waybar button.

### `clipkeys.py` — terminal-aware Super+C / Super+V

keyd owns the chords but doesn't know the focused window; Hyprland does. This
listener watches `activewindow` events and re-binds keyd over its socket:
`Ctrl+C/V` for normal apps, `Ctrl+Shift+C/V` for Ghostty (where plain Ctrl+C
is SIGINT). Needs the `keyd bind` NOPASSWD rule installed by
`run_onchange_after_keyd-sudo-rule.sh`. Re-applies itself every 60s in case
keyd restarted.

### `helium-ws.py` — Helium stays alone

On every `openwindow` event for class `helium`, if the window landed next to
other windows it moves it to the first non-existent workspace id and switches
the view there. Combined with the scrolling layout, that gives the browser
the full work area. Also re-asserts the view when a chromium-style launcher
dies right after spawning the window and steals focus back.

### `cheatsheet.sh` + `cheatsheet.txt` — `SUPER+?` overlay

A ghostty window pre-opened on the `special:cheats` workspace showing the
static keybinding list; `SUPER+?` toggles it. Static on purpose — update
`cheatsheet.txt` when bindings change.
